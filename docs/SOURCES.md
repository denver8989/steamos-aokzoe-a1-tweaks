# Sources and redistribution

- [Valve recovery instructions](https://help.steampowered.com/en/faqs/view/65B4-2AA3-5F37-4227) and [official image index](https://steamdeck-images.steamos.cloud/recovery/). Reviewed Steam Deck image: `steamdeck-oobe-repair-20260707.10-3.8.14.img.bz2`; compressed SHA-256 `4254ee02ec34ae8add9aceef1881a2ce675a9d0176171df92e0eaa1bf014c594`, expanded SHA-256 `f9aa0fa2dd618febf28a5e2a583d1e2b5a8ca3f1205be965da584602ac962f40`, expanded bytes `8120172544`. The full vendor script, OS image and vendor binaries are not redistributed. The narrow recovery diff is applied locally only after the stock script hash matches; upstream material remains subject to its original terms.
- [ValveSoftware/SteamOS issue 2515](https://github.com/ValveSoftware/SteamOS/issues/2515) is background for drive-specific recovery trouble, not proof of this user's earlier error.
- [ChimeraOS device-specific configurations](https://github.com/ChimeraOS/chimeraos/wiki/Device-Specific-Configurations) documents the A1 incomplete-EDID issue and firmware overrides. [frzr-bootstrap](https://github.com/ChimeraOS/frzr/blob/master/frzr-bootstrap) uses ordinary partitioning and filesystem creation. No frzr implementation is copied here.
- [Bazzite hardware setup](https://github.com/ublue-os/bazzite/blob/main/system_files/desktop/shared/usr/libexec/bazzite-hardware-setup) identifies the original A1 EDID override. The payload source is [bazzite-firmware-nonfree](https://github.com/ublue-os/bazzite-firmware-nonfree/blob/main/usr/lib/firmware/edid/aokzoea1ar07_edid.bin); expected SHA-256 `85a76fda934a88aa08fe6c2575da82a834160071a8e76c20de16cb79d3003e70`. Bazzite's main code repository license does not establish redistribution permission for every firmware file in the separate nonfree repository. We could not establish a clear license for this EDID, so **neither the binary nor an archive containing it is shipped**. Installation fetches it from upstream or accepts a user-supplied identical file and verifies the checksum. An upstream change fails closed. This project's license does not grant rights to upstream firmware.
- [Official Codex CLI documentation](https://learn.chatgpt.com/docs/codex/cli) and [OpenAI rust-v0.166.0 release](https://github.com/openai/codex/releases/tag/rust-v0.166.0). The optional downloader pins the three official release-asset digests returned by GitHub. No executable, account, token, session or other credential is bundled.
- The standby workaround comes from the reported runtime A1 investigation: a firmware `SPTS` notification generates an immediate spurious PNP0C0C wake. The repository contains only the minimal AML byte signature used for a guard and synthetic tests, not the machine's DSDT, journals or serial information.

Own original code is MIT-licensed. This does not relicense referenced firmware, Valve material or optional downloaded tools. No distribution affiliation or official device support is implied.


## Optional post-install extras

- [Decky Loader](https://github.com/SteamDeckHomebrew/decky-loader), its [installer](https://github.com/SteamDeckHomebrew/decky-installer/blob/main/cli/install_release.sh), and pinned release/service metadata. The setup uses the official binary and native service layout, keeping detected existing installations.
- [SimpleDeckyTDP](https://github.com/aarron-lee/SimpleDeckyTDP), release 1.0.7. Reviewed `plugin_settings.py`, `settingsSlice.ts` and advanced-options schema: the optional preset changes only the default profile's `tdp`, ensures the slider can reach 30 W, and enables the plugin's TDP control. Existing per-game and other controls remain.
- [CSS Loader](https://github.com/DeckThemes/SDH-CssLoader) and [Decky store metadata](https://plugins.deckbrew.xyz/plugins). The GitHub release was older than the compatible store version. Version 2.1.3 is fetched from the store's content-addressed CDN URL and checked against the store's SHA-256. The reviewed build supports theme manifest version 9 and `config_USER.json` / `config_ROOT.json`.
- [Handheld Controller Glyphs](https://github.com/victor-borges/handheld-controller-glyphs), commit `a7eb5ef6d91e1af2d315c73112b5a4eec7b10939`. Its theme manifest explicitly contains the `AOKZOE A1` Handheld option. Both CSS Loader configuration variants are seeded with this choice and activation enabled.

All downloads and digests are listed in `extras/packages.json`. No third-party plugin binary, full plugin source or theme asset is redistributed in the release; these are downloaded from upstream only when selected on the installed device. Their licenses remain upstream.


## Windows and dual-boot integration

- [Valve's Steam Deck image agreement](https://store.steampowered.com/steamos/download/?ver=steamdeck): obtain the original image directly; no OS image is redistributed here. See DISTRIBUTION.md.
- [Microsoft WSL setup](https://learn.microsoft.com/en-us/windows/wsl/install), [mount restrictions](https://learn.microsoft.com/en-us/windows/wsl/wsl2-mount-disk), and [WSL kernel configuration](https://github.com/microsoft/WSL2-Linux-Kernel/blob/linux-msft-wsl-6.18.y/arch/x86/configs/config-wsl). The backend checks actual Btrfs availability; it does not assume that installing userspace tools provides a missing kernel module.
- [InnoVision-Games/steam-os-custom-install](https://github.com/InnoVision-Games/steam-os-custom-install), pinned in `dualboot/upstream.json`. Its full script is not bundled. An opt-in local transform routes partition creation through our verified free-space planner and removes destructive/manual-selection branches. The inspected repository had no license file; our license does not relicense it. The earlier [steamos-dual-boot](https://github.com/InnoVision-Games/steamos-dual-boot) repository is a repair cheat sheet and its fixed-disk commands are not automated here.

- [Rufus](https://github.com/pbatard/rufus), [official download and publisher details](https://rufus.ie/en/), [v4.15 source](https://github.com/pbatard/rufus/tree/v4.15) and [GPL license](https://github.com/pbatard/rufus/blob/v4.15/LICENSE.txt). The optional Windows handoff downloads the unmodified official x64 portable release on demand; no Rufus binary or source is bundled. The release asset SHA-256 is pinned in `windows/rufus.json` and Windows verifies its Authenticode publisher. Only `-i` (image path) is passed; Rufus retains device selection and write confirmation.

- [Canonical Ubuntu 24.04 WSL root filesystem](https://cloud-images.ubuntu.com/wsl/releases/24.04/20240423/) and its [official checksums](https://cloud-images.ubuntu.com/wsl/releases/24.04/20240423/SHA256SUMS), pinned in `windows/ubuntu.json`. First-use setup downloads and verifies the archive locally before WSL 2 import; it is not redistributed. See [Ubuntu terms](https://ubuntu.com/legal/intellectual-property-policy) and [Microsoft WSL commands](https://learn.microsoft.com/en-us/windows/wsl/basic-commands) for `--no-distribution` and `--import --version 2`.
